# KUT 설치 안내

Win64 후보 패키지를 설치하고 확인하는 방법입니다. 이 패키지는 UE 5.8 Win64에서 플러그인이 제대로 설치되고 로드되는지 확인하기 위한 내부 검수용 후보본이고 학생에게 나눠 줄 완성본은 아닙니다.

Claude Code 실행 파일은 들어 있지 않습니다. 학교 ChatKHU를 거쳐 실행할 때의 제공 조건과, 학생 PC에 런타임을 설치하는 방법은 아직 확인하는 중입니다.

## 준비

- Windows x64, 그리고 이 후보본을 빌드한 것과 같은 UE 5.8 설치본이 필요합니다. 엔진 패치 버전이나 BuildId가 다르면 다시 빌드해야 할 수 있습니다.
- 엔진에 들어 있는 ToolsetRegistry 플러그인과, 그 플러그인이 쓰는 엔진 플러그인을 그대로 씁니다. 패키지에는 엔진 플러그인을 넣지 않았습니다.
- ModelContextProtocol 플러그인은 없어도 됩니다. MCP 서버나 터미널, Node.js, 전역 CLI 설정도 따로 준비할 필요가 없습니다.
- 실제로 질문하려면 개인 ChatKHU API 키와 네트워크 연결, 남은 크레딧이 필요합니다. 개인별 월 한도는 ChatKHU에서 관리합니다.

## 설치

1. 설치할 프로젝트의 에디터를 닫습니다. 전에 설치한 적이 있다면 프로젝트와 플러그인 폴더를 먼저 백업해 두세요.
2. 압축을 풀고 후보본 안의 `KHUTutor` 폴더를 프로젝트의 `Plugins` 폴더 아래에 복사합니다. `프로젝트/Plugins/KHUTutor/KHUTutor.uplugin` 경로가 되어야 합니다.
3. UE 5.8에서 Blueprint 전용 프로젝트를 엽니다. `Edit > Plugins`에서 KHU UE Tutor가 켜져 있는지 확인하고 필요하면 에디터를 다시 시작합니다.
4. `Window > KHU Tutor`로 패널을 엽니다. Blueprint Editor에서도 같은 메뉴로 그 에셋의 패널을 열 수 있습니다.
5. C++ 빌드나 모듈을 다시 빌드하라는 창이 뜨면 진행하지 마세요. 엔진 버전과 BuildId, 플러그인이 두 군데 설치되지 않았는지부터 확인합니다. 다른 엔진용으로 빌드한 DLL을 복사해 넣으면 안 됩니다.

검수할 때 화면에서 볼 것은 패널 열기, C++/CS 실습을 고른 뒤 입력 내용이 유지되는지, 학습 기록을 저장하고 다시 열어 확인한 뒤 복사하는 데까지입니다. 실제 질문과 노드 이동은 승인된 런타임이 준비된 환경에서 이어서 확인합니다. 새 프로젝트에서 헤드리스로 로드되는지와 화면에서 쓰기 편한지는 따로 확인합니다.

## 학생용 설정

10월 26일 rc4부터는 `templates/Config`의 값을 패키지에 넣습니다. 요청 반복 상한은 기본 T1이 3회, T2가 5회이고 작업 예산은 soft 240, hard 800 크레딧입니다. 반복 상한이나 soft 예산에 걸려 멈추면 알림에서 '계속하기'로 이어 가거나 '여기서 멈추기'로 끝낼 수 있습니다. hard 예산에 걸리면 더 이어 갈 수 없습니다. 개발 환경에서 쓰는 20회 설정은 학생 패키지에 들어가지 않습니다.

## 키 등록과 오류

승인된 Claude 런타임이 있는 환경에서 패널의 설정 화면에 본인의 ChatKHU 키를 입력하고 연결을 확인합니다. 키는 그 프로젝트의 `Saved/KHUTutor`에 Windows DPAPI로 암호화해 저장되고 배포 패키지에는 들어가지 않습니다. 키 발급과 학교 계정 권한은 학교 안내를 따릅니다.

| 화면이나 증상 | 확인할 것 |
|---|---|
| Claude 연결 프로그램이 준비되지 않았다는 안내 | 후보본에는 실행 파일이 없습니다. 담당자가 확인한 런타임 제공 절차가 필요합니다. 이미 설치된 `claude.exe`가 있다면 설정의 고급 설정에서 위치를 지정합니다. MCP 서버를 직접 띄워도 해결되지 않습니다. |
| 인증 실패 | 키에 오타가 없는지, 만료되지 않았는지, 학교 계정 권한이 있는지 확인합니다. 오류를 알리거나 화면을 공유할 때 키가 보이지 않게 하세요. |
| 잔액을 조회하지 못함, 잔액 미확인 | 인증이 된 것으로도, 잔액이 0인 것으로도 보면 안 됩니다. 네트워크와 서비스 상태를 확인합니다. |
| 크레딧이나 작업 예산 안내 | 실제로 보내는 질문은 크레딧을 씁니다. 작업 예산과 개인 월 한도는 서로 다른 값입니다. |
| 응답이 끊기거나 시간 초과 | 쓴 질문은 따로 남겨 두고 연결을 확인합니다. 중단된 요청에도 비용이 들었을 수 있습니다. |
| 모듈을 찾을 수 없음 | 압축이 끝까지 풀렸는지, DLL과 `UnrealEditor.modules`가 있는지, UE 버전이 맞는지 확인합니다. |

튜터가 주는 도움은 L0~L3까지입니다. AI 답변에 나온 코드나 원인, 확인했다는 내용은 직접 다시 확인해야 합니다. 변경 대행(L4)은 꺼져 있고 학생의 C++ 코드를 자동으로 고치거나 빌드하는 기능은 없습니다.

## 제거와 기록

에디터를 닫고 프로젝트의 `Plugins/KHUTutor` 폴더를 지웁니다. 대화와 학습 기록, 피드백, 암호화된 키는 프로젝트의 `Saved/KHUTutor`에 그대로 남으니 필요한 기록은 먼저 백업해 두세요. 플러그인을 지워도 기록은 자동으로 지워지지 않고 지울지는 학생이 정합니다.

## 제공 조건과 고지

Claude Code는 Anthropic의 별도 소프트웨어입니다. [공식 제품 제공 조건](https://code.claude.com/docs/en/legal-and-compliance#can-customers-offer-claude-code-in-their-products)에 따르면 제품 안에서 Claude Code를 실행할 때는 바이너리를 바꾸지 않아야 하고 사용자가 자기 키나 계정으로 인증하며 사용료도 사용자에게 직접 청구되어야 합니다. 학교 게이트웨이 경로에 어떤 계약이 적용되는지 확인해야 해서 이 후보본은 CLI를 다시 배포하거나 학생 PC에 설치하지 않습니다. 학교 계약에서 허용되는지를 판단한 것은 아닙니다.

Unreal Engine과 엔진 플러그인은 Epic의 제공 조건을 따릅니다. ToolsetRegistry는 사용자의 엔진 설치본에 있는 것을 쓰고 패키지에 복사하지 않습니다. KHU 자체 코드의 외부 배포 라이선스는 일반 공개 배포 전에 정합니다. 내부 검수용 빌드가 성공했다고 해서 배포 허가나 학교 인증을 받은 것은 아닙니다.
